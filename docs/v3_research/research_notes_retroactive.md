# 反向推演（懒提级 / 给定事实倒推合理过去）调研笔记

> 目标：当一个个体/团体/聚落要从粗模拟"提级"为精细对象时，先给定一个当下关键事实，再反向倒推一段能合理化它的过去经历。找出可参考的学术与工程方法。

## 1. 核心思路定性：这是"溯因推理（Abduction）"问题
- **演绎**：因→果（已知规则与原因，推结果）。**归纳**：多个观察→规律。**溯因（Abduction）**：果→最佳解释的因（inference to the best explanation）。福尔摩斯式推理。
- 我们的需求正是溯因：**已知"现在的关键事实"（果），求"最可能、最自洽的过去经历"（因）**。
- 学术对应：**Abductive Commonsense Reasoning / αNLG（abductive natural language generation）**（Bhagavatula et al. 2019, 引用 565+）——给定 O1（先前观察）和 O2（之后观察），生成中间最合理的解释 H。可直接映射为：给定"角色当下状态"，反推"导致该状态的经历"。
- 反向解码方法：**Back to the Future: unsupervised backprop-based decoding**（EMNLP 2020）——专门处理"反事实/溯因"文本生成，从结局反推过程。

## 2. 工程范式一：懒生成 / Just-in-Time（按需生成，量子坍缩式）
- **核心思想**：世界大部分处于"叠加态/未定义"，只在被观测（玩家到达、剧情触及）时才"坍缩"为确定的细节。没被看到的就不浪费算力，也保留了未来自由编织的空间。
- 工程对照 **Wave Function Collapse (WFC)**：本质是**约束满足问题（CSP）**——每个"格子"初始持有所有可能状态的叠加，坍缩一个后沿约束传播（belief propagation）收窄邻居的可能性，直到全局自洽。
- 映射到本项目：一个"待提级"的聚落/团体/人，初始只有少量已确定的宏观约束（库存、岗位、晶石产量、和某势力关系紧张）。提级时，把"过去经历"当作待坍缩的格子，在满足这些宏观约束 + 世界史一致性的前提下，坍缩出一段具体历史。

## 3. 工程范式二：符号约束 + LLM（保证自洽的混合架构）
- **Answer Set Programming (ASP) 引导 LLM 故事生成**（arXiv 2406.00554, 2024）：先用 ASP 这种声明式逻辑求解器生成满足所有硬约束的"故事大纲骨架"，再交给 LLM 填充自然语言血肉。
- 价值：**硬约束（事实不能矛盾）交给符号求解器保证，软质感（生动叙事）交给 LLM**。这正好解决"反向推演的经历不能和已有世界史打架"的核心难题。
- 同类：**ASP narrative planning with Theory of Mind**（AAAI AIIDE）——能在反推经历时让角色行为符合"当时他知道什么、相信什么"，与本项目的信念/常识系统天然契合。

## 4. 工程范式三：程序化叙事的连贯性护栏（直接可抄的工程技巧）
来自《Procedural Narrative and How to Keep It Coherent》与 Hades 实践：
- **前置条件（Prerequisites）+ 守卫子句（Guard Clauses）**：反推出的每段历史必须通过条件校验（不能出现"已死之人又出场""没有的物品被评论"），不满足就丢弃重生成。Hades 用了上千条这类条件。
- **优先级排序的事件牌库**：候选的"过去经历"按与当前事实的契合度排优先级，优先选最贴合的。
- **三类一致性必须守住**：① 连续性（Continuity，因果/生死/物品不矛盾，最可量化）；② 基调（Tone）；③ 节奏（Pacing）。反向推演主要守"连续性"。

## 5. 工程范式四：DF 式"快进史" vs 反向式"按需史"（两条路线的取舍）
- **Dwarf Fortress / Caves of Qud**：世界生成时**正向快进**整段历史（aging the world），全量预生成。优点是绝对自洽（因为真的跑过一遍），缺点是算力昂贵、且大量历史永远用不到。
- **本项目的反向懒生成**：平时只跑粗粒度统计，**不预生成个体细史**；只在需要时反推。优点是省算力、聚焦故事；代价是必须额外保证反推出的历史与已发生的宏观史不矛盾——这正是上面 CSP/ASP 护栏要解决的。
- **折中（推荐）**：宏观层正向快进（保证大事件骨架真实存在，如某次矿镇覆灭、商路断裂、迁徙冲突确实在统计层发生过），微观个体史按需反向填充（把这个角色"挂"到已存在的宏观大事件上，例如"他的家族因那次商路断裂而流亡"）。如需为遗物或高潮补足来历，也应优先复用已有锚点；只有在不改写宏观历史时，才允许新增局部、低影响的微型锚点。

## 6. 与既有系统的衔接
- **信念/常识系统**：反推出的经历应当能解释该角色"为什么持有这些常识/偏见"。
- **分级调度器**：反向推演正是"提级"那一刻被触发的核心动作。
- **故事定义/叙事调度**：反向推演就是"反向圆故事"在个体史层面的实例化。

## 可参考模型/方法总表
| 子问题 | 可参考方法 |
|--------|------------|
| 理论定性 | 溯因推理 Abduction；αNLG 溯因自然语言生成；反事实反向解码 |
| 按需生成（省算力） | 懒生成 / Just-in-Time worldbuilding；WFC（约束满足 + 信念传播的"坍缩"） |
| 自洽保证 | ASP/CSP 符号求解硬约束 + LLM 填血肉；ASP + Theory of Mind |
| 工程护栏 | 前置条件/守卫子句、优先级牌库、连续性/基调/节奏三一致性（Hades） |
| 宏微折中 | DF 正向快进宏观骨架 + 个体史反向挂接（呼应既有"反向推导"知识） |
