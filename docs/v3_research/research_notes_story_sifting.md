# Echo V3 故事筛选（Story Sifting）调研与头脑风暴笔记

本文用于补齐“故事筛选”方向的预研记录。它不定义最终实现接口，而是整理 Echo V3 当前最需要验证的问题：世界持续运行时，如何从大量事件流中识别出“值得讲、说得通、可追溯、可介入”的故事。

## 一、研究对象

故事筛选不是故事生成。Echo V3 的基本口径是：

- 世界先正向运行，产生人物行动、关系变化、岗位危机、商路震荡、迁徙、势力松动和传说传播。
- 故事筛选器从事件流中识别具有叙事结构的片段。
- 反向推演只补足人物细史、遗物来历和局部伏笔，不能替代正向运行出的因果链。

因此，故事筛选器的工作不是问“我要生成什么剧情”，而是问：

> 世界刚刚发生的哪些事，已经具备一个故事的骨架？

## 二、Echo V3 的故事最低条件

一个候选故事至少要满足四个条件：

1. **剧烈震荡**：世界状态发生了足够明显的变化，例如死亡、背叛、断供、迁徙、岗位失效、商路改道、首领合法性下降。
2. **焦点人物**：震荡直接影响了一个或多个具体人物，而不是只有抽象数值变化。
3. **因果链**：能回答“起于何事、谁做了什么、造成什么后果”。
4. **扩散或可介入**：事件要么从个人扩散到团体/聚落/商路/势力，要么能降级成玩家可参与的局部问题。

不满足这些条件的事件可以记录为日常日志，但不应进入故事池。

## 三、基础故事模式草案

### 1. 背叛模式

```text
长期信任/服从
  -> 收益诱惑或怨恨积累
  -> 违约、泄密、叛逃、倒戈
  -> 具体受害者与关系破裂
  -> 团体、商路或势力后果
```

适用来源：商队信用崩塌、护卫断饷、首领强征、亲族旧怨。

筛选关键：背叛者和受害者必须有可追溯关系；背叛后必须改变关系、声誉或资源流。

### 2. 复仇模式

```text
重大伤害
  -> 记忆烙印与仇恨形成
  -> 可行动目标出现
  -> 报复行动
  -> 新伤害或和解机会
```

适用来源：杀亲、夺矿、见死不救、祭司煽动、战争幸存者。

筛选关键：复仇动机不能只来自阵营标签，必须来自个人经历或反向挂接的历史锚点。

### 3. 商路危机模式

```text
风险上升或路线中断
  -> 下游短缺/涨价/断饷
  -> 具体人物被迫行动
  -> 走私、护送、掠夺、强征或叛逃
  -> 商路恢复、改道或衰亡
```

适用来源：Alpha 污染、生物部落迁入、渡口失守、商队盟主封锁道路。

筛选关键：断供必须传导到具体岗位、团体和人物动机，不能只停留在价格数字。

### 4. KOL 崛起与团体裂变模式

```text
共同凝聚物下降
  -> 断层张力超过阈值
  -> 断层侧候选 KOL 浮现
  -> 追随者沿关系网转移
  -> 新团体成立或旧团体重组
```

适用来源：首领战败、矿脉枯竭、预言失败、分配不公、外乡人涌入。

筛选关键：新 KOL 必须能解释其威望或资源基础，追随者必须和他在关系/理念/利益上更近。

### 5. 迁徙冲突模式

```text
原居地推力
  -> 沿关系网迁徙
  -> 接收地资源与信念压力上升
  -> 偏见、岗位竞争或治安冲突
  -> 融合、隔离、暴力升级或再迁徙
```

适用来源：灾害、饥荒、征收、战争、岗位崩塌。

筛选关键：迁徙目的地不能随机；接收地必须出现可观察的经济、关系或信念后果。

### 6. 遗物出土与历史回声模式

```text
玩家/聚落接触旧世界遗存
  -> 调用已有历史锚点或局部未细写锚点
  -> 补足遗物来历、幸存者或禁忌
  -> 当前人物获得新动机
  -> 信念、声誉、势力或任务写回世界
```

适用来源：废墟、旧战场、封闭矿井、庇护炉、旧祭坛。

筛选关键：反向推演只能补足来历，不能改写宏观历史。

## 四、候选事件打分维度

候选故事可以先用 0-1 的设计强度近似评分：

| 维度 | 问题 |
|------|------|
| 震荡强度 | 状态变化是否足够大？ |
| 焦点人物强度 | 是否有具体人物被改变命运？ |
| 因果完整度 | 是否有起因、行动和后果？ |
| 扩散层级 | 是否波及团体、聚落、商路或势力？ |
| 动机可追溯 | 能否追到需求、记忆、信念或关系？ |
| 玩家可介入性 | 能否降级为护送、清剿、谈判、调查、救援等局部玩法？ |
| 写回价值 | 玩家结果能否改变库存、关系、声誉、商路、合法性或信念？ |

一个临时近似：

```text
故事候选分 =
  震荡强度
+ 焦点人物强度
+ 因果完整度
+ 扩散层级
+ 动机可追溯
+ 玩家可介入性
+ 写回价值
- 日常重复惩罚
- 因果断裂惩罚
```

## 五、事件窗口与故事边界

故事筛选必须解决“从哪里开始、在哪里结束”的问题。

- **开始**：第一个使焦点人物命运或团体状态明显偏离原稳态的震荡。
- **中段**：后续事件持续沿同一因果链扩散，且焦点人物/核心关系仍有关联。
- **结束**：震荡进入新稳态、焦点人物目标达成或失败、冲突双方关系重组、商路恢复/改道/废弃。

如果没有明确结束，故事会变成无限追踪的历史流；如果结束过早，后果无法写回世界。

## 六、原型验证问题

第一版原型不需要复杂叙事生成，只需要验证以下问题：

- 事件流中能否稳定筛出“有焦点人物”的候选故事？
- 同一条故事能否追溯到至少 3 个因果节点？
- 玩家介入后，是否有至少 1 个世界状态被写回？
- 关掉反向推演后，故事数量是否下降但不归零？
- 提高世界压力时，故事密度是否上升，但是否会导致故事边界混乱？
- 提高故事门槛时，是否能减少日常琐事入选，同时保留重大事件？

## 七、与现有验收文档的衔接

- `echo_v3_module_acceptance_criteria.md` 定义故事必须“因谁而起、起于何事、波及多广”。
- `echo_v3_full_chain_social_simulation_model.md` 定义事件流进入故事筛选，再沉淀为记忆、传说、偏见和历史锚点。
- `echo_v3_retroactive_backstory_criteria.md` 负责补足人物细史和奖励前因，但不负责制造主要因果链。
- `echo_v3_full_chain_parameterization.md` 中的故事门槛、焦点人物权重、因果链完整度权重和奖励溯源要求，可作为第一版调参旋钮。

## 八、下一步调研方向

- 继续查阅 Story Sifting / emergent narrative 中的模式匹配方法，比较事件图、时间窗口和叙事谓词三种表示方式。
- 设计 3-5 个固定故事模式的纸面事件表，手工跑一轮，检查是否会误收日常事件或漏掉重大事件。
- 为每个故事模式定义最小事件字段：参与者、动作、资源变化、关系变化、地点、时间、来源、后果。
- 验证故事筛选器如何与玩家任务生成解耦：先筛故事，再决定是否可玩；不可玩的故事仍应进入历史纪事。
