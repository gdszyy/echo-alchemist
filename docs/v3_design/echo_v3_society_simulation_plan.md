# Echo V3 经营开放世界肉鸽：社会模拟架构与重构 Todo

> 本文档基于 echov2 现有的四层元胞自动机世界模拟器（地幔、气候、晶石、生物），结合“经营 + 开放世界肉鸽”构想，设计出从个人到世界的四层社会模拟架构，并以“晶石经济”为核心资源驱动整个中世纪背景下的文明变迁。

## 1. 核心设计理念

Echo V3 将从纯粹的“弹珠肉鸽战斗”转向“**世界模拟器驱动的经营肉鸽**”。在底层驱动方面，现有的纯数据引擎将继续演化地形、气候与晶石灾害，为游戏提供动态的物理环境。在这个世界中，晶石（分为高能的 Alpha 和惰性的 Beta）不仅是能源，更是驱动所有社会活动的硬通货与核心资源。

为了在保证深度的同时控制算力消耗，文明的重构采用了差异化策略。大多数生物部落仅维持简单的繁衍、领地划分、采矿与灭绝逻辑，作为环境背景与野外遭遇战的载体存在。而少数被称为“人类复制人”的群体，则具备复杂的四层社会关系。每次人类灭绝后，系统会通过复制人机制使其重生，从而严格控制模拟的人口基数。在战斗内核上，现有的子弹属性系统（如火、冰、雷、激光等属性层数）与符文机制将被保留并包装为“炼金武装”，用于人类团体对抗晶石灾害、清理野兽部落或处理势力间的冲突。

## 2. 四层社会模拟架构

为了将现有的粗颗粒度聚落细化，人类社会将采用四层嵌套架构。非人类生物部落则停留在第二层，不具备复杂的社会网络。

### 架构层级定义

| 层级 | 颗粒度 | 核心属性与机制 | 行为逻辑 |
| :--- | :--- | :--- | :--- |
| **第一层** | 个人 (Individual) | 包含生存欲望（健康、饥饿、贪婪）、战斗能力（子弹属性层数）以及对其他个体的认知记忆。 | 由状态机驱动，执行寻找食物、开采晶石、寻求庇护或发起社交互动等原子行为。 |
| **第二层** | 团体 (Group) | 表现为家庭、采矿队、商队或雇佣兵小队。内部存在信任网络，可能因晶石分配不均而分裂。 | 形成共同目标，如商队会基于地形通行代价在城市间寻找最优路径进行晶石交易。 |
| **第三层** | 城市 (City) | 依托地形建立的实体（如易守难攻的盆地）。拥有晶石库存、物价指数、繁荣度与文明程度。 | 派出采矿队开采 Beta 晶石，消耗晶石维持城市防护罩与人口繁衍，并通过市场吸引商队。 |
| **第四层** | 世界 (World) | 多个城市组成的联盟或王国。基于对晶石矿脉（特别是地幔源井）的争夺形成地缘政治。 | 指令通过信使传递，受地形与距离导致的通信延迟影响，边境城市易发生自治演化。 |

## 3. “故事”单位的定义与生成机制

在模拟器中，“故事”并不是预先写好的静态剧本，而是系统主动识别出的剧烈状态变动的封装。它是玩家介入游戏、体验肉鸽玩法的切入点。

一个标准的“故事”必须具备明确的开始与结束条件。故事的开始通常源于剧烈的震荡变动，例如某地突发 Alpha 晶石狂潮摧毁了重要商路，或是某大城市晶石耗尽导致暴乱。这种变动必须剧烈地影响了某个关键人物，进而波及整个团体或城市。玩家作为“回声炼金师”介入变动，利用战斗解决危机。当变动源被消除或目标实体灭绝时，故事结束，系统生成历史纪事并结算奖励。

在故事生成机制上，系统借鉴了 AI 驱动 RPG 叙事的反向推导原理。首先，系统根据当前局势决定需要生成何种级别的冲突（例如需要一场掉落火焰符文的战斗）。随后，系统在当前网格中寻找合理的伏笔进行反向推导，例如发现某城市附近有 Beta 矿区，便生成“采矿队遭遇变异火属性野兽袭击”的背景。最后，将抽象的冲突实例化为具体的个人、小团体和战斗关卡。

## 4. 架构重构 Todo 清单

为了将现有的 `echov2` 和老 `echo` 仓库改造为 V3，需要执行以下阶段性任务规划。

### 阶段一：老仓库清理与 V3 基础搭建
首先需要清空 `echo` 仓库的旧代码，仅保留必要的构建配置和 README，将其作为 V3 的新工作区。随后，将 `echov2` 的核心世界引擎完整移植到新仓库，作为底层的物理法则引擎。同时，将子弹实体、属性配置、碰撞与伤害计算等模块剥离并移植，作为 V3 的战斗结算模块。

### 阶段二：数据结构扩展与社会层引入
在纯数据引擎之外，需要建立一个 `SocietyEngine`，采用实体-组件系统（ECS）或关系图数据库来管理个体与社会关系。在此阶段，需要依次实现个人实体、团体寻路与交易逻辑，并将原有的人类聚落升级为接入市场定价模型的城市实体。同时，简化非人类生物的逻辑，使其仅作为环境阻碍存在。

### 阶段三：故事生成器与肉鸽玩法融合
开发独立的 `StoryEngine` 以监听世界和社会的剧烈变动事件。实现反向推导逻辑，将变动事件转化为任务委托或突发事件。接着，将这些“故事”中的冲突与底层的打砖块战斗关卡连接起来，确保敌人的属性和词缀由发生地的气候和晶石状态决定。玩家将扮演游走于各城市间的独立势力，接受委托赚取晶石。

### 阶段四：UI 视图与可视化
最后，开发基于 Canvas 或 WebGL 的宏观大地图 UI，渲染网格、地形高度、晶石分布与商队轨迹。提供微观社会 UI 面板以查看城市信息和物价。整合并翻新原有的战斗界面，使其在玩家进入故事节点时能够无缝切入。
