# Echo V3 叙事反向推演系统：机制说明与涌现目标标准

在庞大的世界模拟中，如果每个个体的每一秒都进行精细计算（如 Dwarf Fortress 的正向快进），算力成本将无法承受，且大量无用历史会被白白抛弃。因此，项目采用了“分级调度器”：绝大多数对象平时只进行粗粒度的数值模拟，只有当玩家接近或关键剧情触及时，才被**“提级”**为精细对象。

提级的核心难点在于：**必须给定一个当下的关键事实，然后反向推演（倒推）出一段合理化的过去经历，让这个对象显得“一直活在世界里”**。本文档基于溯因推理（Abduction）、懒生成（Just-in-Time Worldbuilding）与约束满足工程实践，给出这套“反向推演（懒提级）”系统的机制说明与验收标准。

## 一、 机制说明：如何给定事实、倒推经历

反向推演在学术上属于“溯因推理（Abductive Reasoning）”[1]。即已知结果（当前状态），推导出最可能、最自洽的原因（过去经历）。

### 1. 混合架构：宏观正向快进 + 微观反向挂接

为了兼顾算力与自洽性，系统采用宏微观分离的架构：
- **宏观层（城市/势力大事件）**：在世界生成和推进时，**正向真实跑出**。例如，“晶石矿坍塌”、“南部爆发三年战争”、“商路改道”这些大事件，是作为硬骨架真实存在于世界历史数据库中的。
- **微观层（个体/小团体细史）**：平时只记录简单的统计标签（如：难民、贫穷、信仰 A）。当触发“提级”时，系统通过**“挂接”**的方式，将这个角色的经历绑定到已发生的宏观大事件上。

### 2. 约束满足与“坍缩”（WFC 式逻辑）

当一个角色被提级时，他处于“未定义的叠加态”。系统的任务是让他的过去“坍缩”为唯一确定的历史。这个过程被建模为一个约束满足问题（CSP）[2]。

系统必须守住三类约束护栏（Guard Clauses）[3]：
- **硬性连续性（Continuity）**：反推的经历不能与角色的当前状态矛盾（如当前一贫如洗，反推经历不能是刚刚继承了晶石大矿而未被劫掠），也不能与宏观历史矛盾（如自称参加过一场根本没发生过的战争）。
- **关系网络自洽**：反推的恩怨必须在现有的关系网络中找得到落点，不能凭空捏造一个不存在的世仇家族。
- **常识/信念溯源**：反推的经历必须能够完美解释该角色当前“信念集（Belief Set）”中的偏见或常识是怎么来的。

### 3. ASP 骨架 + LLM 填充（符号与神经网络协同）

为了保证约束绝对不被打破，同时保证叙事的生动性，系统采用两步走策略 [4]：
- **第一步（符号求解）**：使用类似 Answer Set Programming (ASP) 的逻辑求解器，输入当前状态和宏观历史库，求解出一条满足所有硬约束的**“因果骨架”**（如：地点 A -> 遭遇事件 B -> 失去亲人 C -> 形成偏见 D -> 迁徙至当前地点）。如果不满足约束，求解器会重新掷骰。
- **第二步（自然语言生成）**：将这个无矛盾的骨架作为 Prompt 注入给 LLM，由 LLM 负责“填血肉”，生成带有情绪色彩、符合角色性格的自然语言文本和对话回忆。

### 4. 反向圆故事的“爽点”机制

正如既有知识库（AI 驱动 RPG 叙事引擎反向推导机制）所指出的，反向推演不仅用于填补背景，更是**制造叙事爽点**的利器。
当系统判定需要给玩家发放一个“遗物”或高潮奖励时，系统会先确定这个结果，然后**反向新建或调用一个符合大背景的简单历史事件框架**（如一场被遗忘的大战），将这个遗物的来历合理化，使其显得“本就该如此，草蛇灰线”，而非天降之物。

## 二、 涌现目标验收标准

当这套反向推演系统放入游戏后，它必须让玩家感觉这个世界是“全息且一直运转的”，察觉不到“懒生成”的痕迹。

### 目标一：无缝的“提级”体验（薛定谔的 NPC）

**在社会里扮演的角色**：用极低的算力成本，维持一个表面上极其庞大且细节丰富的世界幻觉。

**合格标准**：
- 玩家随便在一个偏远村落拉住一个此前从未被精细模拟过的路人，该路人能立刻讲出一段与其当前穷困潦倒状态完全吻合的过去。
- 这段过去不仅解释了他的现状，还能完美解释他为什么极度仇恨某个势力（与他的偏见/信念集对应）。
- 玩家回头去查阅世界宏观历史，发现路人提到的那场“毁了家乡的旱灾”确实在世界史记录中发生过（微观成功挂接宏观）。

**不合格信号**：
- 提级后的角色讲出的历史与世界大势完全割裂（如提到一场战争，但宏观历史上该地区过去百年全是和平）。
- 角色讲述的过去无法解释他现在的处境或持有的常识。

### 目标二：严格的因果连续性（不穿帮）

**在社会里扮演的角色**：确保程序化叙事不会因为随机拼接而变成荒谬的笑话。

**合格标准**：
- 反向推演的历史绝对不会出现“死人复活”、“时空瞬移”等逻辑硬伤。
- 如果两个被提级的角色在反向推演中被设定为“曾经是战友”，那么当这两人相遇时，系统必须能识别这层关系，双方的反应必须符合这段被“倒推”出来的共同经历。

**不合格信号**：
- 角色回忆中提到被某人杀死，但该角色现在活生生地站在玩家面前。
- 角色自称世代居住于此，但其身上却带有刚刚从极寒之地跋涉而来的环境 Debuff。

### 目标三：反向圆故事的戏剧张力

**在社会里扮演的角色**：作为“隐形导演”，通过倒推伏笔来让戏剧高潮显得合情合理。

**合格标准**：
- 当玩家在一个随机生成的废墟中发现一件极其强大的晶石遗物时，系统能立刻反向推演出一段关于这个废墟的悲壮守卫战历史。
- 这段历史不仅解释了遗物为什么在这里，还能顺理成章地将废墟外某个游荡的疯癫 NPC 设定为当年的幸存者。整个因果链严丝合缝，仿佛剧本早就写好。

**不合格信号**：
- 强力遗物或关键剧情转折毫无来由地出现，系统无法为其提供任何合理的背景解释，让玩家感到“系统在作弊”或“只是为了发奖励而发奖励”。
