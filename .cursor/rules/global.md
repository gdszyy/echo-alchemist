# 全局架构规范 (Global Architecture)

## 1. 架构概述

Echo V3 是一个以晶石为核心资源、中世纪背景下的经营 + 开放世界肉鸽游戏，其核心是一个**自发产生故事的世界模拟器**。

系统由五个层级构成，从底层物理世界到顶层叙事：

| 层级 | 名称 | 来源 | 状态 |
|------|------|------|------|
| L0 | 地形/气候/晶石模拟 | 继承自 echov2 的 `world_sim` | 已成熟 |
| L1 | 个体层（生物/人类/核心人物） | 待建设 | 调研中 |
| L2 | 团体层（权力/裂变/临时聚合） | 待建设 | 调研中 |
| L3 | 城市/经济层（晶石经济/商路） | 待建设 | 调研中 |
| L4 | 世界/势力层（地缘/迁徙/通信） | 待建设 | 调研中 |
| L5 | 叙事层（故事定义/筛选/反向推演） | 待建设 | 调研中 |

## 2. 核心工作流串联

当前阶段（预研期）的工作流：

```
领域调研（v3_research/）
    → 产出涌现目标验收标准（v3_design/*_criteria.md）
    → 未来：基于标准设计具体算法/模型
    → 未来：基于 echov2 world_sim 接入实现
```

叙事生成的核心闭环（目标状态）：

```
世界模拟（L0-L4 持续运转）
    → 故事筛选器检测震荡事件
    → 触发"提级"：反向推演补全个体细史
    → 叙事层生成可讲述的故事
    → 故事追溯回具体个人的动机与经历
```

## 3. 全局禁止行为清单

1. **禁止在调研未完成前产出具体游戏机制设计**：验收标准文档只定义"涌现什么效果"，不规定"如何实现"，禁止跳过调研直接写实现方案。
2. **禁止破坏"代码-文档同步"契约**：在修改任何架构设计、API 或核心逻辑时，必须同步更新 `.cursor/rules/` 下对应的规范文档。
3. **禁止硬编码凭证信息**：在所有文档示例和代码中，严禁出现真实的 API Key、Token 或密码。
4. **禁止跳过流程洞察沉淀**：在任务中发现隐蔽逻辑或耦合陷阱时，必须在 `.cursor/rules/process_insights/` 中记录对应洞察。
5. **禁止手动编辑自动索引**：`.cursor/rules/auto_index/` 目录下的文件由 `code-indexer` 脚本自动生成，严禁手动编辑。
6. **禁止将调研笔记与验收标准混写**：`v3_research/` 只存原始调研笔记，`v3_design/` 只存经过提炼的设计与标准，两者严格分离。
